## Install

Select the guide matching your installed distribution, release and package architecture. Each guide covers requirements, quick installation, manual repository setup and updates.

<a id="platforms"></a>

The supported releases and architectures are generated from the publisher's target definitions. Package availability per project, release and architecture is on the [status pages](status/README.md#banner).

## Signing keys

Verify downloads with the [signing keys](keys/README.md#banner) for your package manager. Keys are shared across architectures; keep signature verification enabled.

## Troubleshooting

[Diagnose installation errors](docs/troubleshooting.md#banner), or compare available packages and replacement builds on [project status](status/README.md#banner).

## How publication works

Packages is the generated destination for signed feeds, installation guides and recorded build status; DistributionPackages owns publication. See the organization [workflow graph](https://github.com/SNodeC/.github/blob/main/docs/workflow-graph.md#banner) for the build, signing and dependent-build chain.

[Read the column meanings and publication model](docs/publication.md#banner). Maintainer operations belong to DistributionPackages.

## Contributing

Report installation issues in [Packages](https://github.com/SNodeC/Packages/issues). Documentation and publisher changes belong to [DistributionPackages](https://github.com/SNodeC/DistributionPackages#banner). Do not edit generated feeds, keys or status pages by hand.
