# CI orchestration

## Authority and activation

The master [`ci/projects.json`](../ci/projects.json) is an allowlist, not an active product or target inventory. A verified source tag notification writes its pinned full JSON into version-addressed `status.json.requests[project][tag]`. Only verified direct notifications write this request slot; row-scoped cascade captures never replace it. Having any such request activates the allowed repository; activation survives a capture/build failure. Counters do not activate products. Inactive repositories are not selected, read as products, cascaded or displayed. The organization-wide capacity observer still inventories all organization Actions jobs.

The exact selected commit owns `ci/packages.json`, root `VERSION`, dependencies, full target matrix and hooks. Central code owns generic platform capabilities, runner mapping, signing and feed layout. No default-branch product source or split integration pin is used. The wrapper dispatch ref may be the source's default branch; build source and hooks always come from the immutable tag archive.

## Selection and execution

- A direct created/moved tag builds that exact SHA and version, including an older supported version.
- A publication owning the highest current prerequisite receipt on a target can admit an active dependent's **highest numeric semantic-version tag**. A chain never chooses the latest moved tag, last-published source or pending direct request. Annotated tags are peeled; one tag listing fixes tag and SHA at capture. Definitions and archives are pinned to that SHA.
- Missing published prerequisites close direct rows as `unsatisfiable`, naming the missing prerequisite. They do not implicitly build prerequisites. Activation remains. Recovery is a highest-tag cascade after prerequisites publish, an operator retry, or another tag notification; missing-prerequisite closure does not automatically rebuild an old direct tag.
- Normal cascades wait for every required arm on the same row. One gate checks published arm bindings and already selected cascade versions/revisions, including arms published outside the root lineage. A current older arm cannot discharge a higher selected arm still running or failed. The gate runs at capture admission, child build admission and publication. Chains recurse and diamonds join once for the resolved baseline. There is no full-matrix barrier or graph-atomic feed promotion.
- A highest tag with invalid/missing integration, VERSION mismatch or an omitted row fails/excludes only the affected capture/row with a reason. Transient reads defer with bounded backoff; there is no older-source or branch substitute.

## Capture, callbacks and publication

Intake verifies the direct origin's repository, push event, workflow path, tag, SHA and numeric run ID. Forged/unallowlisted/non-semver notifications do not activate or reserve. Identical source notifications are idempotent. Per-version request-time ordering prevents an old event replacing a newer request for the same tag; different versions coexist.

Reservation is a required CAS transaction, before capture counts as started. At that fresh-state boundary it validates the prospective highest-semver requested graph, replacing only the notified project/tag slot. A rejected cycle or namespace collision changes no remote counters, allocations or activation. Intake still validates the direct selected definition, including an older tag; a lower request never replaces the higher graph definition. Capture failure remains visible; registration does not depend on rendering. Capture checksums cover source archives, profiles, rows and allocated revisions; tooling is an ancestor-checked coordinator commit. A saved capture is immutable, including across tag moves. An expired capture requires a new release.

The existing orchestration workflow also accepts coordinator-only row-specific cascade captures. An admitted parent intent and App actor must match the ledger. A source notify App cannot authorize that route or activate an inactive repository. The capture chooses the current highest tag, reserves its row revision under the sharing rule below, and uses the same prepare/archive/CAS path. Parent handoffs and child captures share the existing execution ledger and observer; capture jobs consume capacity. The child's registered generation owns the build after handoff, even while the parent run's aggregate status still lags. An unregistered in-flight capture continues to defer matching work; the parent status and commitment still follow observed execution facts. Same-version supersession requires a registered generation covering that row or a newer published revision on that row. An unregistered direct reservation only defers matching work; a failed reservation lifts that deferral. Late callbacks cannot revive excluded superseded work. Current work and root-held captures are indexed once per pass from the existing ledger. Outstanding work defers fresh captures; settled work, including failed captures bound to that baseline, prevents duplicate retries by another root. A requestless held capture in backoff does not defer a direct build. Before new capture admission, the holding root retires its requestless non-terminal nodes when that root is no longer current on the row, the dependent is no longer selected there, or other recorded work already satisfies the baseline. Retirement is `superseded`, retains the count and observation history, and is visible to other roots in the same pass. A queued or otherwise in-flight intent is never retired; it resolves through ordinary observation first. Retrying a holder under an inert root retires that holder and directs recovery to the current root. Historical roots and older-version publications never initiate cascades. No eager dependent archive path remains.

Row-scoped cascade captures may share a revision across targets when their selected tag, exact source SHA, tooling commit and all prerequisite source/revision identities match at reservation. This release-provenance projection excludes architecture-specific file checksums; it promises neither equal bytes nor identical full build inputs. `reserve` alone records its digest in the held capture's `source.inputs`, alongside run and attempt. The existing work index supplies registered row claims and held captures. A live or registered matching capture may donate its highest revision only when it exceeds all valid claims on this target/version: published and registered work, the current direct request, and linked reservations on that row (conservatively across versions). An unregistered terminal link remains a claim but cannot donate. Otherwise the project counter supplies a fresh number. Direct captures always allocate fresh numbers. The existing per-project whole-workflow concurrency group is part of the uniqueness guarantee; removing a link alone does not revoke an already-passed intake.

A replay keeps its allocation only with the same recorded digest. Changed or missing provenance on an unsaved cascade rerun fails closed: retry the held node through Coordinate package builds for a fresh capture decision. Saved bundles remain immutable. The digest disappears with the execution link on transient failure or no-artifact operator retry; abandoned unregistered allocations are not a strictly increasing history. Valid registered row/version identities and accepted publications remain monotonic. Different row histories, tag/tooling changes or prerequisite revisions may still diverge the numbers; there is no matrix barrier. A shared number identifies separate captures per row, not one project-wide capture. Stale pinned re-admission retains its exact source/revision and may later use newer prerequisites on one row. Full ownership/checksum checks at admission and publication are unchanged.

Source requests carry target/runner, capture, intent, exact feed baseline commit, full prerequisite definitions and minimal pinned ownership facts. Source jobs have only coordinator/own-repository reads. They do not fetch sibling JSON. The `_commit`/`package` facts must match baseline source commits before reuse. Reuse verifies every dependency byte; native installation uses exactly that selected set, and SDK imports share the same ownership policy.

Callbacks are claims. DP verifies source run/attempt/job, workflow, actor, target, artifact ID/digest and downloaded ZIP bytes before signing. Trust is “built in the source run,” including wrapper-added jobs; there is no SLSA or exclusive-recipe claim. The actual triggering actor is checked on authorized reruns. Source credentials have no signing secrets or feed write authority.

The serialized `package-publication` group and Git leases provide single-writer atomic publication and preserve unrelated updates. APT InRelease/Release.gpg, RPM packages/repomd, opkg/usign and OpenWrt APK indexes are signed and verified against neutral key files in `keys/`. Before indexing or signing, the trusted publisher reads each own and retained package control and applies the shared namespace, expected version/revision and architecture policy; filenames and source inventories alone do not establish ownership. Duplicate internal identities are rejected. The opkg index is regenerated from those verified IPK controls, including retained packages even when an earlier index was empty. The APK index must contain exactly the verified identities. Admission and publication independently check the **same** dependency identity: exact source, revision and owned file checksums. Stale work finishes, is rejected and re-admitted with its exact selected source when overlap rebuilding is enabled. Converting a still-active direct artifact into dependent work happens before the same arm gate; no build or publish is admitted while its arms are stale. This conversion never resets terminal failures or exhausted budgets. A gated non-terminal artifact displays pending with its blocker reason, and publishing resumes only on admission. With overlap disabled the pinned rebuild closes with “pinned rebuild disabled by rebuild_overlap.” A genuinely new prerequisite publication can still admit a fresh highest-tag capture; the setting does not disable that separate recovery path.

Controller request and node updates carry the exact value read as a transient CAS base. The existing metadata writer applies a change only if that entry still equals the base; otherwise it preserves the concurrent result for the next pass. Dispatch requires its intent to have been accepted durably. The sole narrow exception is an execution acknowledgement for that same admitted intent/run: it may record the consumed-attempt floor once and retain or fill the execution binding, without replacing a concurrent status, reason, artifact, newer attempt or different intent. This also covers a lost dispatch response when the authenticated child reservation already bound the capture run. Replaying an acknowledgement cannot count twice. These bases and acknowledgements are temporary writer inputs, not new ledger fields. Operator retries still act on current remote state and reset the selected budgets deliberately.

## Versions, inventories and display

The existing per-target `build.json.releases[project][tag]` owns each supported version's latest publication: source, revision, verified receipt and owned signed/unsigned files. Aggregate source/version/receipt views are derived from the highest published semantic version. Unsigned build artifacts carry actual package versions for reused prerequisites; feed entries record their revisions directly. One shared identity/ownership policy serves both lifecycle shapes.

Allocation counters increase globally per project only for fresh decisions; eligible cascade reservations may reuse an earlier allocation above their row claims; stale/replay comparison is **within the same semantic version**. An older direct version cannot suppress, supersede or reject a higher version merely by receiving a higher allocation. Each version retains its latest published revision, not every build attempt. Sibling products and SDK exports survive all four format publications. Same-version replacement feeds the existing 30-day unreferenced-file retirement process, including by-hash indexes. No automatic old-version support cutoff or offboarding policy is introduced.

Status is a projection, never execution authority. One reducer chooses the highest requested/captured semantic version, then revision/attempt for that version. New higher versions display from pending, including capture failure; a failed higher version never falls back to an older success. The global release label shows only the source version; row cells retain actual package revisions. Displayed state, time, release label, availability and real source-job link remain unchanged during an older direct build, callback and publication. Internal ledger/receipt writes still occur. Available/Published describe only that highest entry; an unpublished highest version has no available package or borrowed older timestamp. Capture handoff jobs never masquerade as source jobs. Titles are escaped and no fake run/coordinator link is substituted.

The trusted publisher takes incoming ownership facts only for the captured releasing source. Sibling namespace facts come from their pinned publication entries; untrusted sibling source substitutions do not redefine file ownership. The same validator requires each resolved owner to have an expected version. Package names and filenames reject control characters in this same validator, covering source staging and every own/retained indexed binary. Native staging validates copied prerequisites against baseline versions and its own files against the captured version.

## Admission and observer cost

Strict cause priority is publication, then dependent/overlap work (including captures), then direct releases. Graph position is not cause. There is no fairness/root injection, preemption or work-conserving exception. Drain arguments assume bounded arrivals and retries.

Capacity defaults to the documented organization plan mapping, observing **all** organization repositories and jobs. Hosted jobs `in_progress` with an allocated runner count as occupied; unrelated queued backlog is reported, not subtracted. Standard x64 and arm64 are conservatively counted against one total; self-hosted jobs do not consume it. Larger/macOS sublimits are not separately scheduled. Headroom defaults to 2 for control/signing/publication. A running control job is already occupied and reduces its own headroom requirement, avoiding double counting. Count-then-dispatch is best-effort, not an enforceable reservation against unmanaged workflows.

Each admitted source/capture/publisher intent holds a commitment while `waiting` is true, even after local terminal scheduling. An observed allocated job replaces it with occupancy; observed terminal execution releases it. A known queued run has no time expiry. An unbound intent retires only after a successful no-match listing beyond the existing 30-minute window. Unknown/malformed/404/scope/rate-limit/transport observations never prove absence. A run appearing after verified post-window absence is counted once occupied: this remaining underestimate is documented best-effort. Deduplication uses run/job/intent identity.

An observation costs one `orgs/{owner}` call + ⌈repos/100⌉ inventory pages + five status listings per repository and their pages + one paginated jobs listing per active run. At 43 repositories, this is at least 217 calls before jobs/reconciliation. Waiting non-published nodes, including terminal ones, add a run lookup plus a paginated jobs listing when bound, or paginated intent lookup when unbound, subject to per-node backoff. A completed terminal run needs no jobs listing. The real token rate limit/visibility and throughput effect are unvalidated live hypotheses.

Unknown plan/known inventory mismatch/API or listing failure admits no new consuming work, including publication; built artifacts are retained. Capacity is observed only on wakes with candidates after its retry deadline. Transient observations back off (bounded at 1800 seconds, with retry hints); configuration errors report actionable reasons and retry after 30 minutes. One node's error does not abort unrelated reconciliation; capacity observation itself fails closed globally.

## Recovery

Callbacks drive normal build completion. A rejected callback still permits the bounded reconciliation pass, then fails the control run so the rejection remains visible; the rejected claim itself changes no ledger facts. DP capture/publication workflow completions wake control. Each control wake performs one bounded pass; it downloads only captures needed by non-terminal work, once per process through one shared callback/reconciliation loader. Both callers use the same expiry check, checksum verification and atomic temporary-directory rename; a callback’s verified capture is reused by the subsequent tick. Unchanged terminal nodes do not re-download bundles. Waiting terminal nodes still refresh execution facts without changing scheduling status, cause, artifact or budgets. Completed source jobs awaiting publication are not repeatedly fetched.

The static ten-minute schedule at UTC minutes 3, 13, 23, 33, 43 and 53 covers lost callbacks and unrelated jobs finishing; Actions provides no cross-repository completion subscription for unmanaged jobs. Idle passes do no capacity inventory. There is no permanent busy loop or external service. Scheduled wakes may be delayed/dropped, and public-repository schedules may be disabled after 60 days of inactivity. No timing SLA is claimed. If a node is transiently deferred and no work remains in flight, it waits for the next delivered scheduled control run, a source/workflow event, or an authorized operator wake without retry after retry_at. A wake does not reset node budgets or drop an execution commitment. This CI remains self-contained on GitHub: no external scheduler, self-dispatch chain or in-job recovery timer. The offset only reduces exposure to busy boundaries; no measured delivery improvement is claimed.

Each admitted cascade selects its highest tag only at its own fresh capture boundary. Configuring a direct/root capture validates the selected definition with already recorded active graph facts; it does not eagerly fetch peers. Actual prerequisite definitions and ownership are bound from the row's pinned publication before admission.

A failed Python intake/prepare in an admitted cascade uploads `capture-result-{attempt}` from the existing capture job. The observer verifies coordinator workflow/run/actor, admitted intent, attempt, artifact association, ZIP paths and digest before accepting the shared failure category. A transient result defers that row with bounded backoff and retains its build count; after observed terminal execution a current holder can retry with a fresh capture and a revision selected by the same sharing rule. If its root was replaced during backoff, retirement releases the old holder and the current root re-evaluates the row. A direct completion can settle a still-current holder instead of starting a duplicate capture. Configuration/integrity/expiry failures, missing results and mismatched bytes fail closed with an operator reason. The result is execution evidence, never a package artifact or a ledger writer. No signing secret is included. Capture attempts share the existing three-build budget, separate from publication retries. Failed result observation adds one artifact-list request (with pages) and one verified ZIP download to that node's reconciliation. Git and gh commands through the shared runner have 120-second subprocess timeouts. Real Git process errors and timeouts use the transient classifier and the same bounded three-capture budget. Reservation/status initialization failures before the Python capture failure handler produce no result artifact: inspect logs and retry as an operator; absence is never success.

Build/capture and publication dispatch budgets are separate (three each). A failed build or publisher job is terminal until operator action or a separate new event; deterministic is the scheduling category, not proof of the underlying root cause. Transient retries within a job do not imply automatic failed-job dispatch retries. Transient/gate/observation failures do not consume publication retries. Deterministic, configuration, expiry and exhausted-budget failures remain terminal with their original reasons and budgets. A binding change never reopens those old nodes. A genuinely new highest-current prerequisite publication may admit a fresh highest-tag capture instead. Superseded stale work retains its exact pinned source on re-admission, under the same arm gate; it is never paired with a parallel fresh capture. An expired build artifact rebuilds source; an expired capture needs a new tag notification. An identical receipt does not sign again or rewrite package manifests, indexes, signatures or retention. With unchanged authored content it produces no new feed commit; an authored-content refresh may still produce a commit without changing publication facts. Conflicting bytes under one identity fail closed.

Use **Coordinate package builds** on the coordinator default branch. An authorized human may retry `capture/project/target` or dispatch without inputs after repairing capacity access. Retry resets that node's budgets, reuses a valid artifact, and rebuilds if it expired. Inspect `status.json.runs[capture].nodes[target/project].observation` for category/reason/deadline. A 404 may mean expired **or inaccessible**. An unregistered capture request remains eligible and reserved while its run cannot be observed; backoff and an observation reason are the only changes. Recovery is a new verified tag push event for the same tag (a moved tag with matching VERSION, producing a new source workflow run), which replaces that request through CAS. Rerunning the same source run is still a duplicate. The node retry input addresses registered nodes, not unregistered requests. Only a confirmed completed capture without registration makes that request ineligible. Retrying an unobservable publisher or terminal queued node deliberately releases its commitment and can duplicate a still-queued execution; repair/inspect access first. There is no implicit abandon command.

`queue: max` is finite (up to 100 pending runs). Reconciliation can recover lost callbacks, not a lost manual retry. Inspect and re-request manual operations when necessary. Notify App Actions:write retains a denial-of-service ability through cancellation/artifact deletion, without gaining signing authority.

## Local verification

Run `tests/run_package_checks.py` with the actual three source worktrees and the documented actionlint binary. Tests use local bare repositories, mocked transport and disposable test signing keys; no installs or live writes. Real OpenWrt signing is skipped when usign/APK tools are absent. The subprocess guard rejects remote Git/gh/install commands; it is not a universal HTTP sandbox.

Actionlint 1.7.12 schema exclusions are limited to `client-id`/missing `app-id` for create-github-app-token@v3, `queue` on concurrency, and documented `job.workflow_repository`/`job.workflow_sha` context properties. These exclusions are not runtime validation. Official context documentation: https://docs.github.com/en/actions/reference/workflows-and-actions/contexts#example-usage-of-job-context-workflow-identity . Dispatch `return_run_details`, created filters, queue behavior, triggering actors, token installation scopes and real runner contention remain live-validation items.

Authored `site/` guides and other deployment content refresh on every successful publication, including an identical receipt replay. The copy carries existing generated README blocks forward, and a README lease merge carries the remote blocks. A later best-effort control render is the only producer of new block content; required capture recording and signing never depend on it. Highest-only byte stability covers version-derived status/overview/README blocks, not authored content edits. “Latest release” is the highest source semantic version, without a project-wide revision. Available shows its package version without Current/Outdated icons. In build retains work-state icons and derives Waiting/Blocked labels from highest-only row activity, current-root capture facts and immediate dependency links, without network discovery or ledger writes. Indirect waits appear before capture; waiting labels invent no revision. HTML target tables center only `—` and left-align labels. The existing internal revision fallback for rows without that publication is unchanged and is not a global label. A failed selected arm remains recorded on its own node; a join page links to its blocking immediate arms without creating a synthetic ledger node. Direct builds retain presence-only admission; they do not acquire the cascade arm gate.

The organization observer relies on an operator-verified **All repositories**
fine-grained PAT scope. It paginates the organization repository listing in
full and checks private/public totals only when GitHub supplies the optional
private count. Omission of that count is not a zero-private-repository claim.
A token changed to **Only select repositories** can silently omit unselected
private repositories and their jobs; runtime completeness cannot independently
detect that case when counts are absent. Keep All repositories selected,
including for future repositories. Source Apps retain their narrower scopes.

## Public-key authority and operating limits

The publication workflow overlays default-branch `site/`, `install/` and `keys/`; capture-pinned executable tooling stays immutable. Feed public keys come only from that deployed overlay. Before signing, the captured verification key for the row's family must equal the overlay key byte for byte (`apt.asc` for APT/RPM, `opkg.pub` for 24.10, `apk.pem` for 25.12); a mismatch fails closed and requires a fresh capture. Publishing one family cannot restore another family's old captured key. Rotation and secret provisioning remain separate operator actions. Drain active publishers before changing keys and their matching signing secrets; the overlay is selected at job preparation, not continuously refreshed during a running transaction. After an authorized rotation, old captures for that family must be replaced; re-signing already-published rows is an explicit operator procedure, never automatic.

Do not remove an allowlisted repository while it has request records: offboarding is out of scope. Artifact ZIPs have verified origin/digest/path safety but no separate entry-count or expanded-size quota; a trusted source can cause denial of service within job/disk limits. Parentless feed snapshots can orphan exact baseline commits. Availability over real queue ages remains a live hypothesis, with no new retention/ref mechanism. Sandbox-only capacity workflows and deliberate negative fixtures are deployment test content and are excluded from canonical coordinator code.
